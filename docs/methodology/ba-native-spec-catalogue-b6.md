The §8.3 advisory renders once if Solution stands waived — decomposing on a waived Solution is decomposing a guess; the BA's call stands.
2. **Framework act:** candidate sweep across the estate — canvas Core Functions lines with their `→ O-n` links (the primary capability ground) · T-13 journeys (journey-shaped groupings) · Third-Party connection rows (integration-shaped candidates) · out-of-scope `deferred — roadmap candidate` rows (ready-made candidates carrying phase hints — D-B5-5's graduation path) · domain-model clusters and role-owned ground as grouping evidence · the mined area checklist (§7) applied as probes: **a probe is a recall check against estate evidence, never a generator** (principle 4, D-B6-10) — it fires only where estate evidence grounds it; absence is declared, never filled (the honest-absence rule, inverted onto the reference's mandatory first epic — §7).
3. **Framework act:** draft the set — per candidate: name, description at the locked shape, Source lines; sized by the framework test: **one epic = one scoping call and 1..N features** — a call is 30–60 minutes with ≤ 12 must-asks (elicitation D1), and slicing lands 1:1 for a small epic, 2–3 features for a large one (plan §5/C3). A candidate a single story would cover is too small; one whose essential scope exceeds a call, or would slice past ~3 features, is split. **Every Source citation carries its ground-class (D-B6-11):** `[stated]` where an estate line states the capability directly — a canvas Core Functions line, a journey, a connection row, a hard client request — and `[inferred]` where the row exists by dependency reasoning or by a probe firing on indirect evidence (a role model implying access, a flow that presumes accounts). **Both classes are legal rows:** coverage-complete stands exactly as §2 states it and the class rules nothing out — it makes derivation visible at birth, for the readers one run and one band downstream. A row is `inferred` only when every one of its citations is; a single `[stated]` citation makes the row `stated`.
4. **Framework act:** coverage & exclusivity pass — every Core Functions line resolves to exactly one row's Source (an unresolved line is a hole; a double-resolved capability is an overlap — both surfaced, never silently settled) · each deferred out-of-scope row either graduates (proposed routed pair: the new row cites it; the out-of-scope row resolves to the named epic) or holds with a basis · a candidate contradicting a standing `not planned` exclusion surfaces as a conflict for BA ruling (D-B5-5's other direction). Output: the decomposition report — the set · coverage map · graduations · conflicts · open edges.
5. **BA act:** rules — merge, split, rename, drop, add; settles conflicts and open edges (whatever stays open is carried as honest description adjacency for the kits' §3.2.D boundary checks); approves the set (Q2 — the framework's set is advisory, the composition is the BA's).
6. **Framework act:** write `roadmap.md` — rows at stable `E-<nn>` (assigned in this run, never reused — D-B6-2), Phase `Unallocated`, Status `Defined`; the approved graduation batch routes (elicitation §3.5 discipline); the armed scoped-H fires silently on the writes (contract §3; gate §10.2). The run closes recommending the initial allocation (T-18) in the same sitting — C1's first trigger, and what makes every row whole at the Tier-1 shape before any kit reads it.

1. **BA act:** invoke on a C1 event or by election (P-O3); the run records under `## Band 2` (D-B6-5) with its trigger named. The invocation optionally carries **directives** — free text, or explicit `<epic> → <phase>` moves, with reasons where the BA gives them (D-B6-9; parsed at step 3).
2. **Framework act:** evidence assembly — the current rows and standing log (the last entry is the diff baseline) · briefs where they exist (essential scope, boundaries, §5 assumptions & risks, §8 slicing breadth) · constraints (time-bound and business rows) · canvas value ground (`→ O-n` links; P-line severity) · dependency ground: domain-model relations, connection rows, the journeys the core value line crosses · resolved out-of-scope rows (phase hints on graduated epics) · **the scope frame** — the ledger head's `Boundary:`, `Budget:`, `Scope decisions:` and derived `Capacity:` lines (orchestrator §2.4 · §8.1), read-only (D-B6-7, its read extended by D-B6-12 on the record — an SD is ground the four locked factors read, never a fifth factor) · delivery state (statuses, closed cycles) on rerun. 3. **Framework act:** the recommendation — per epic a phase and a reason tagged with its deciding factor(s); the walking-skeleton rule stated once: **MVP composes the thinnest end-to-end slice of the core value journey — an MVP row earns its place on that slice or as its dependency.** Rendered as the diff vs. current: changed rows in from → to form, held rows one line. Where an allocation is blocked on an open scope question, the recommendation names the question and the Tier-1 act that answers it — never guesses the answer (principle 3 at phase grain).

   **The scope-frame advisory (D-B6-8) — one per run, on the record; the orchestrator §8.3 advisory pattern: visibility, never a block.** *Number-free form, always:* every epic sitting in a phase **inside the delivery boundary** without a trace to either legitimacy test — (i) the product cannot meet its business goal without it, or (ii) the client hard-requested it in the docs — is named, with what is missing. **The ground-class reads mechanically (D-B6-11):** a `[stated]` row carrying a hard-request citation satisfies test (ii) on its face, and `[inferred]` rows inside the boundary are the advisory's **first-named candidates** — first-named, never disqualified: an `[inferred]` row the product cannot meet its goal without passes test (i) exactly as a stated one does. **The SD reading rule (D-B6-13):** a standing SD trimming a capability is **the later, negotiated client statement** — an earlier hard-request citation **no longer satisfies test (ii) *on its face*** for that capability, and an epic sitting inside the boundary on that citation alone is a **first-named advisory candidate** — first-named, never disqualified: test (i) still passes it where the product cannot meet its goal without it; the controlling-statement law is elicitation principle 4's (D13), cited and never restated. Visibility, never a block; the BA's call stands. The two tests are the composition half of **principle 4** (elicitation preamble); the class is what makes them checkable at the row, and it settles nothing on its own. *With `Capacity check: on`* (orchestrator §8.1) the advisory adds the rough comparison, explicitly assumption-grade: *"MVP phase ≈ \<n\> eng-h against capacity ≈ \<m\> — rough, assumption-grade. Slide-down candidates: \<epics\>."* With the check `off` the advisory stands in its number-free form and nothing else changes. Its record is the run output and the plans-file run log (orchestrator §7.3) — **never the roadmap**: that file carries outcomes and reasons only (D-B6-4), and a capacity figure written into it would breach the numbers-in-advisory-prose-only rule. The BA's call stands, as always.

   **The advisory is a decision list, not prose (D-B6-14).** Every finding the advisory names takes an **`ADV-<n>`** id from the orchestrator's register — the `Scope advisories:` head line (orchestrator §2.4 · D-O68) — and the advisory renders as **one numbered decision list** in the **P-A1 row shape** (source-audit definition §5 — cited, never restated): each row the finding with its **verbatim citation**, lettered dispositions, and a default. **Three dispositions.** **(a) `hold as advisory — no move` — the default:** visibility preserved, nothing moves, the row returning at the next run for as long as the finding stands. **(b) `direct a move → <phase>`:** pinned in this run's diff as a **`BA-directed (ADV-<n>)`** row (D-B6-15) — never an inline phase edit, D-B6-4's column ownership standing. **(c) `accept — <reason>`** with an event-shaped revisit trigger, on the **SA record pattern** (source-audit definition §5): the entry moves to `accepted <date>` on the head line and **returns to the list the moment a new source or a new `SD-<n>` re-asserts the finding**. **`apply all` is a complete, safe ruling**, every row's default holding. **Visibility, never a block; the BA's call stands** — what changes is that the call is now **taken and recorded**, where prose beside a diff could be approved without ever being read. **Under a standing grant the same list rides the orchestrator's two reports** (orchestrator §10.7 · D-O69); **assembling it may be AUTO, ruling it never is**.

A directive that conflicts with a factor produces a **named advisory in the same diff — never a block**. A partial directive ("X into MVP", nothing else) leaves the framework to propose what slides down to fit.
   2. **Not phase-shaped** → **routed as proposals, never executed inline** (D-B6-4's column ownership stands): a split, merge, or new epic proposes a T-17 rerun · "cut it entirely" proposes `Later` or a retire act, the BA picking · a cost question is answered in capacity-check prose, not a diff.
   3. **Impossible** — an unknown epic, an off-vocabulary phase, self-contradicting directives → **named lines in the response**, never a silent skip.

An SD-driven run rides the existing **`scope-frame`** trigger; no new trigger token exists.

   One run → one diff → one approval → one log entry, whatever the input shape.
4. **BA act:** edits and approves — C1 verbatim: the BA edits and approves; the approved diff is the ruling.
