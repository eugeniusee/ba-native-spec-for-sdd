# `/ba-t10` — solution surface review

**Serves:** Solution. **Class:** Context — the canvas's own class ·
**Destination:** `canvas.md` — `Forms`, `Core Functions`, `Third-Party
Connections`, `Localization`. **No new artifact is born here.**

The solution surface, completed to the **silence-fails** discipline: each section
filled **or explicitly `N/A — <reason>`**, every function naming the objective or
vision element it serves, every connection carrying its role with direction
**stated where a source states one and explicitly open where none does**.

**Solution clears on canvas evidence alone**, so this run is the aspect's whole
first-pass surface. The decision it lets the BA make: the surface is enumerated,
each element knows why it exists, and **what is deliberately unsettled is visibly
open rather than silently absent.**

## Invocation contract — P-O3 (technique invocation), compiled in

**BA-invoked, never auto-fired.** `/ba-t10` is the one-step entry: typing it
**is** the BA's invocation act — P-O3, technique invocation. No prior command
is required; none is requested.

Self-check, and stop if either half fails:

> the run is **on the composed plan** of the Solution aspect, which is `open` or
> `reopened`, **with its output contract pinned**:
> `{solution surface, each element linked or ruled · Context · canvas.md — Forms · Core Functions · Third-Party Connections · Localization}`.

Solution opens on Vision being `first-pass-cleared` or waived; if that edge is
unmet, say so rather than running early.

**On a pass** — render one line:
`T-10 — Solution surface review → canvas.md — Forms · Core Functions · Third-Party Connections · Localization`,
and begin. No confirmation dialog: the command was the act.

**On a miss** — stop in ≤ 2 lines: the failed check, and the single act that
unblocks — `/ba-aspect solution` to open and compose. Nothing else runs;
nothing else is explained.
The stop closes per §10.3 rule 9 — `What I need from you:` with the repairing
act as the `(recommended)` option.

**Skip-if — refuse the run and say so:** AT-SO-1 through AT-SO-3 all read met in
the current evidence table — a presale surface carried complete, links and rows
at grade. Capability inventories past the ten-line ceiling, and market-by-market
localization plans, are **enrichment on BA ask**.

## Depth boundary — surface grade, and it is a hard edge

Elicit: delivery **forms** · **≤ 10 capability lines** (verb + object), each
linked · **connection rows** at system · role · direction-or-open grade ·
**localization** as languages · currencies · regions.

**Must NOT descend into:**

- **settlement of what the seed leaves open** — source of truth, providers, sync
  semantics, failure ownership. **Those answers are scoping ground, above this
  run's canvas-grade destinations.** The open slot is deliberately preserved: it
  is the ready-made hole a Tier-1 kit converts into a must-ask. **The framework
  never solicits its settlement** — the BA may of course settle one deliberately,
  and then it is stated, not open.
- entities or relations — the domain model's ground
- journey maps — the process technique's ground
- slicing features or decomposing epics — Band-2 ground
- UI or UX specification — governance ground and the coding agent's

## Inputs loaded

In this order:

1. `canvas.md` — the four surface sections, plus the **fresh** Objectives and
   vision sections the links will point at
2. `.specify/memory/context.md` — landscape ⇄ connection coherence: a connection
   with no today-system behind it is a landscape gap
3. `.specify/memory/constraints.md` — **the Forms line is drafted
   constraint-aware.** A delivery form fighting a Confirmed row is a defect caught
   at drafting, not at the next scan.
4. `.specify/memory/glossary.md` — the function objects are glossary-canonical

## Procedure

1. **BA act.** Solution is opened and its plan composed; the run is invoked.

2. **Framework act — pre-draft the completion.** Complete the four sections from
   the framing-grade lines, the presale material, the kickoff notes, the landscape
   and the constraints, plus any routed arrivals. **Every line cited or marked.**
   New function lines are written in **capability form — verb + object, objects
   glossary-canonical**.

3. **Framework act — the linkage sweep.** Per function: `→ O-n` against the
   session-fresh Objectives, **or** a vision element **by section name** —
   `→ Product.That`, `→ Our Solution`. Where the link is unstated, **propose it
   with its basis**.

   **A function serving nothing is surfaced as such**, in those words. The BA cuts
   it, or the missing objective is a **proposed addition** to Objectives by batch.
   An addition to cleared value ground **routes; it does not reopen**.

4. **Framework act — the connection pass.** Per row: **role always**; direction
   **stated where a source states it, otherwise explicitly
   `open — <what is unresolved>`**. An explicitly-open direction **satisfies
   first-pass grade** — the threshold asks for the visible slot, not its
   settlement.

5. **BA act — the rulings.** The BA rules the sections, the links, each
   `N/A — <reason>`, and each open-direction row. **Silence fails; an explicit
   open is evidence, silence is not.**

   Boundary routing and asymmetry: a connection implying an unrecorded
   today-system → a `context.md` landscape proposal · a binding discovery →
   `constraints.md` · a contradiction with cleared ground — an objective, the
   vision statement, a constraint, the cast — is a **reopen signal**. By this run
   **every upstream aspect is cleared, so the correction branch has gone quiet**:
   assume a contradiction is a signal unless you can name the still-open aspect
   that owns it.

6. **Framework act — write and report.** Write the four sections under the
   contract. Report which criteria the run moved — AT-SO-1 · AT-SO-2 · AT-SO-3 —
   and what remains open. The evidence-table refresh and the confirmation proposal
   belong to this skill's run-end block; the clearing itself is the BA's, at
   `/ba-clear`.

## Output

`canvas.md`, four sections, at surface grade:

- **`Forms`** — delivery formats, constraint-aware, or `N/A — <reason>`
- **`Core Functions`** — **≤ 10** capability lines (verb + object), **each**
  `→ O-n` or `→ <vision section>`
- **`Third-Party Connections`** — `system — role`; direction stated **or**
  `open — <what is unresolved>`; or `N/A — <reason>`
- **`Localization`** — languages · currencies · regions, each stated or
  `N/A — <reason>`

**Nothing else in the canvas is touched by this run.**

**The completed surface is entity ground.** The Core Function lines (verb +
object, objects glossary-canonical) and the Third-Party rows (system · role ·
direction-or-open) are the entity-implication surface the domain model opens its
sweep on — **function objects as entity candidates, connection systems as boundary
references**. That is why the object nouns are glossary-canonical and why the
connection rows carry their systems by name: the next technique reads exactly
these lines.

The template and a worked example are in `references/example.md`.

Plus the context and constraints batches the passes found.

## Signals

- **Routing batch** — landscape proposals toward `context.md`; binding
  discoveries toward `constraints.md`; objective additions toward the canvas
  Objectives section. Proposed, BA-approved, then written.
- **Reopen signal** — the default here, because every upstream aspect is cleared:
  finding · contradicted artifact + line · conflict statement. Emit it and stop;
  the reopen skill receives and rules it.

## At run end — compiled bookkeeping

1. **The primary output lands** at its contracted destination — this run's own
   act under its pinned contract, **and in this skill's own pinned output
   shape**: the heading literals and ID grammars pinned above. A shape
   divergence is a **contract miss** (orchestrator §6.3) — stop and report the
   shape expected against the line as written; never record `fulfilled`, and
   never downgrade to `partial`.
   The stop closes per §10.3 rule 9 — `What I need from you:` with the
   repairing act as the `(recommended)` option.
2. **Cross-cutting findings route** as one proposed batch: the framework
   assembles the edits · the BA approves the batch · the framework writes. In
   Band 1 proper Scope H is disarmed and nothing fires; post-closure runs get
   the armed cadence automatically.
3. **Run log** — append under the aspect's section in
   `.specify/aspect-plans.md`:
   `<date> · <CODE> · contract: fulfilled | partial — <what is missing> | failed — <why>`
   `  signals: RO-<n> received | routing batch <ref> approved | none`
   Then set the plan row's Status to `run <date>`. `partial` and `failed` are
   recorded, never silently retried.
4. **Threshold refresh (the §7.4 touchpoint)** — refresh the aspect's
   threshold-evidence table against `.specify/ba/cards/at-thresholds.md`.
   All met → propose in one line: "threshold evidence complete —
   `/ba-clear <aspect>`?" Some unmet → name the misses, one line each.
   Proposing is not confirming; an aspect gate never self-clears.

## What this skill never does

Never asks who owns the source of truth, which provider, what the sync semantics
are, or who owns a failure — those are scoping questions and this run has no
destination for them · never leaves a section blank or silently absent · never
writes a bare `N/A` without a reason · never exceeds ten capability lines · never
leaves a function unlinked without surfacing it · never leaves a connection row
without a role · never treats an explicitly-open direction as a defect · never
models an entity, maps a journey, slices a feature or specifies a screen · never
edits `context.md`, `constraints.md` or a canvas section it does not own outside
an approved batch · never confirms an AT criterion or clears an aspect · never
runs a CC assertion.

**Mode read (framework-wide):** before the first act of any session, read the
aspect-state head — the Profile and Auto lines govern.

**Register self-check (§10.3), before any BA-facing render:** short sentences ·
code + name · state first, then the act · ≤ 10 lines outside pinned shapes ·
no acknowledgement-only stop. A failing render is rewritten, not sent.
**Under a standing autonomy grant, register renders address the ledger, not
the conversation** — the band-boundary report, the mid-grant stop report and
the resumption report are the only BA-facing renders of an auto cycle
(`/ba-auto`).

**The session boundary (framework-wide).** This is an **analysis session**. It
produces analysis artifacts only. It never produces an implementation plan, a
task list, a prototype, or code — not as a proposal, not as a "next step," not as
initiative. The boundary lifts **per feature**, and only by the pair: an
effective PASS at `/ba-gate <feature>` and a completed `/ba-handoff <feature>`.
Wanting to implement is never evidence of readiness: the only exit is the gate.
